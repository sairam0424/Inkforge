I spent my first day on a new team grepping through 80,000 lines of code trying to understand where authentication worked.

4 hours. Three teammates interrupted. Twelve dead ends.

I've lived this on both sides. At Ascendion we built AAVA Code — an AI coding plugin for VS Code with 3K+ daily users across 5+ client environments. Every new client onboarding, day one was the same: unfamiliar codebase, no fast way to answer "how does X work?" without interrupting someone. The tooling gap was consistent regardless of how good the code was.

So I built trelix — an open-source code intelligence engine that indexes any codebase and answers questions about it using hybrid BM25 + vector + call-graph search. It works offline. No API key. Single SQLite file. Zero infra.

The three things I'm most proud of:

1. GitHub PR review: `trelix review --pr owner/repo#42 --post-comments` — fetches the diff, retrieves codebase context for each changed hunk, runs an LLM review, and posts findings back to GitHub in one command.

2. Federated search: `trelix search-all "query"` — search across all your repos simultaneously. Built the same fan-out + RRF-merge pattern I used in production multi-agent systems at Ascendion (Pensieve, 2K+ daily users).

3. MCP integration — one command and trelix works inside Claude Code, Cursor, and Windsurf: `claude mcp add trelix -- trelix-mcp`. The open-source version of what I learned building AAVA Code.

The design decision I'd make again: zero infrastructure by default. Vectors, BM25, call graph, symbols — all in a single SQLite file. Most developers don't want to run a vector database just to understand their own code.

1,508 tests. 20+ languages. MIT licensed.
